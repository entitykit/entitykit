# Preparing EntityKit 0.1.0

The consolidated review against `main` includes the alpha.3 corrections and
retained performance work. The target is a coordinated stable `0.1.0` family.
Source packages currently remain `0.1.0-alpha.3`; this document is a review and
release checklist, not evidence of a published or fully qualified stable release.

## Review scope

| Area | Included behavior | Review reference |

## Performance evidence and remaining limits

Local SQLite HTTP comparisons of the alpha.3 stabilization baseline `7a7b4dc`
against retained runtime `3de75c2` covered 231 cells across three rounds and checked
22,561,050 complete responses. Default scalar hydration throughput improved
26–44%, typed hydration 36–46% and scalar projection 60–80%. Explicit compiled
models plus SQLite connection reuse reached 3.03–3.47 times baseline lookup
throughput. These are local comparisons of those revisions, not production
capacity estimates or PostgreSQL/MySQL speedup claims.

A separate October 15 PostgreSQL baseline used retained `7c7ac88`, Node 24.21,
PostgreSQL 18.6 and an Apple M2 with 8 GiB RAM. The database, HTTP server and load
generator shared that machine. The campaign ran three rounds of 3-second warmup
and 10-second measurement cells, with read concurrency 16, write concurrency 1,
and a fresh context per request. The following are median HTTP requests per
second; each bulk request returns 1,000 records.

| PostgreSQL workload | EntityKit dynamic | EntityKit compiled | Prisma 7.10.0 |
| --- | ---: | ---: | ---: |
| Read one record | 8,872 | 15,450 | 13,857 |
| Load 1,000 full scalar entities/records | 244 | 272 | 587 |
| Return 1,000 scalar projections | 618 | 604 | 581 |
| Load 1,000 full typed entities/records | 49 | 52 | 192 |
| Return 1,000 typed projections | 249 | 261 | 209 |
| Read, change and save one record | 2,684 | 3,079 | 4,081 |

Typed records include booleans, dates, JSON and binary data. Projections return
the same selected fields and complete HTTP payloads as full-record reads.
EntityKit reads already use `asNoTracking()`; full reads still create entity
instances and persistence facts, while Prisma returns plain records. Save paths
also have different transaction costs. Variation prevents treating small
differences as proven wins. Full-entity bulk reads remain a material limitation;
projections suit response-only reads but do not preserve entity/save behavior.

This PostgreSQL campaign compares current stacks, not earlier and later versions
of EntityKit. A subsequent experimental JSON optimization failed the broader
retention criteria and is excluded. Its focused gain is not a shipped gain.
Raw cross-ORM benchmark harnesses and receipts remain in the separate local
benchmark repository; reviewers should request those artifacts before relying
on these exploratory numbers as independently reproduced release evidence.

## Before stable publication

- [ ] Complete review of the consolidated changes, public API additions and
  declared support boundaries. Resolve required PR checks on the final revision.
- [ ] Change the root and all seven packages to `0.1.0`, update exact peers,
  CLI/example pins, lockfile and `entityKitMigrationVersion`, and set all seven
  published `publishConfig.tag` values to `latest`. Preserve private example
  versions and historical migration artifacts.
- [ ] Regenerate and review API reports, and write final `0.1.0` upgrade/release
  notes describing the `0.1.x` compatibility line and known limitations.
- [ ] Qualify the exact candidate through both Node verification lanes, runtime
  coverage, all 26 mutation campaigns, live PostgreSQL/MySQL recovery and upgrade
  checks, performance budgets, browser flows and seven packed consumers. A
  previous revision's results do not replace these checks.
- [ ] After review and merge, explicitly authorize the manual stable Release
  workflow on `main`; verify accepted tarballs, registry integrity and promotion,
  then follow the runbook for the signed tag and GitHub release.

The [release runbook](../releasing.md) defines the commands and acceptance gates.
The manual workflow enforces full qualification before publication. Opening or
merging this review does not publish packages or move npm tags.
