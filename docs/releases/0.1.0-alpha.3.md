# EntityKit 0.1.0-alpha.3

This is the coordinated seven-package release candidate after the published
`0.1.0-alpha.2`. Publication requires the complete release workflow on the
final `main` revision. A source version bump is not publication evidence.

## Upgrade notes

Upgrade all used `@entitykit/*` packages together, including providers, CLI,
testing and NestJS. Exact core peers reject mixed family versions. Public API
additions include `compileModel()`, its handle and options types,
`DbContextOptionsBuilder.useCompiledModel()`, and SQLite's
`SqliteDataSourceOptions.maxIdleConnections`. Existing dynamic configuration
and fresh-connection defaults remain available. The migration-version constant
advances with the package family. Default no-op hook parameters use an underscore to mark them
unused; this does not change their types or calling conventions.

Keep applied migration SQL, checksums and recorded SDK versions immutable.
Alpha.1 users still need the reviewed preservation procedure for callbacks
whose SQLite required-key DDL changes under the newer `NOT NULL` policy;
see [Upgrading](../upgrading.md). The compatibility campaign retains alpha.1
and adds independently captured alpha.2 artifacts on all three providers.
Each old SDK seeds its own database before the candidate reads, saves,
applies and rolls back a new migration while preserving the historical facts.

## Correctness and ownership

- Aggregate and group aliases, including computed `__proto__`, become
  enumerable own fields on ordinary objects without changing their prototype.
  MySQL retains mysql2's existing rejection of private-property result names;
  SQLite and PostgreSQL return and preserve those aliases.
- Aggregate counts use the same safe, nonnegative integer validation as
  terminal `count()`. Unsafe or malformed provider values now throw instead
  of silently rounding. Terminal `countBigInt()` remains the exact count
  route; it is not an aggregate-selector function. `sum()` and `avg()` retain
  their documented approximate JavaScript-number behavior.
- Failed PostgreSQL nested scopes roll back to and release their owned
  savepoint. Cancellation immediately after creation follows the same cleanup.
  Cleanup failures preserve the original error and prevent an unsafe outer
  commit; a successfully recovered enclosing savepoint can still recover a
  deeper failure.

## Performance stabilization

Since alpha.2, include loading batches inverse collection edits, uses balanced
composite predicates and respects actual filter/window parameter budgets.
SQLite streams cooperate with the event loop so fast consumers can receive
timer-driven cancellation. Buffered no-tracking queries use local identity
resolution without full tracking snapshots. Generated-value lookup, deletion
acceptance and ordinary relationship detection avoid repeated scans. Normal
builds preserve incremental state; package acceptance retains a clean build.

This candidate also batches Cascade and SetNull inverse collection removals
for ordinary loaded graphs with dense inverse arrays. Accessors, proxies, custom
collections, sparse arrays, optional SetNull foreign-key converters and Added
relationship ownership retain conservative immediate behavior. Converter callbacks
observe earlier inverse removals, and sparse removals skip holes while retaining
explicit `undefined` elements. Public tests
check linear collection work, stored rows, references, tracker state, failed
planning restoration and caller-transaction rollback.

The performance branch adds explicit [compiled models](../compiled-models.md).
An application creates an immutable mapping handle once and selects it for each
context. `configure()` still runs for every context; `model()` is skipped only
when a handle is selected. Initial support covers flat mappings without value
converters, custom materializers, complex properties or object/function defaults.
Unsupported mappings fail compilation explicitly. Contexts retain independent
tenants, trackers, transactions, cancellation and connection leases. Eligible
buffered entity reads reuse field plans; eligible flat projections capture one
owned plan per execution. Constructors, readers, verified writes and persistence
ownership remain live.

SQLite data sources accept an opt-in `maxIdleConnections` limit for filesystem
databases. It defaults to zero and bounds retained idle handles, not active
contexts. Each context owns an exclusive lease. Session-changing SQL and failed
provider operations retire the handle, and disposing a source with active leases
is refused. This feature does not cache prepared statements or support in-memory
databases and file URIs. See the [SQLite package guide](../../packages/sqlite/README.md).

Default paths also reduce operation-scope, snapshot, projection and materialization
work: one shared async-local store retains per-operation ownership; unused tracker,
acceptance and save helpers initialize lazily; ordinary snapshot keys and nonempty
binary comparisons use native operations. Guarded property writes preserve special
keys and inherited setters. Required root-column ordering omits redundant null
placement while nullable and joined values retain their previous rules.

Local HTTP comparisons show improved default throughput and larger opt-in gains
for short requests. Bulk entity hydration remains substantially slower than the
compared stacks, and some write-tail results remain mixed. These observations
cover local SQLite, not PostgreSQL/MySQL performance or production capacity.
Rejected experiments remain excluded; no general speedup multiplier is promised.
See [performance contracts](../performance.md) for the retained behavior and limits.

## Qualification boundary

The lockfile updates `source-map-js` to its compatible patched release,
`1.2.2`. Runtime audits remain strict. Scoped development dependency
replacements remove `braces` and `sprintf-js`; the full-install audit is clean
and no tooling exceptions remain. The guarded compatibility changes are
documented in [the tooling contract](../tooling-dependencies.md).

The dependency refresh qualifies `pg` 8.23.1, `mysql2` 3.24.5, NestJS 12.1.2,
React 19.3.0, Playwright 1.63.0, Jest 30.5.2 and typescript-eslint 8.71.1.
The newer strict lint rules retain the compile-only assertions and use explicit
names for intentionally unused values. Root tooling explicitly pins
TypeScript 5.9.3, matching the package compiler and API Extractor, so npm
peer resolution cannot silently select a different compiler major.

The release scope remains Node 22.13 and Node 24 on the required Linux lanes,
PostgreSQL 18, MySQL 8.4 and Node's bundled SQLite. General bundler, alternative
runtime and operating-system support is not added by this candidate.

Retain successful exact-revision receipts for both Node verification lanes,
runtime coverage, every fresh mutation campaign, live providers, the Next.js
browser flow, historical upgrades and all seven accepted tarballs. The
[release workflow](../../.github/workflows/release.yml) still invokes the full
matrix and publishes only those accepted artifacts. The follow-up stable pass
freezes the documented contracts and repeats state/resource operations;
broader compiled-model support and prepared-statement caching remain separate work.
